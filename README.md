# Threads自動投稿システム（GAS + スプレッドシート）

タロット3択・情弱ポスト・開運ポスト・HSPあるあるポスト・数秘術ポストの5種類の投稿を、
投稿タイプ別シートで「生成 → 内容確認 → 承認(OK)」し、承認済みの投稿だけを投稿キューシートへ
自動転記してスケジュール投稿するシステムです。

## 全体フロー

1. **生成**（手動実行）
   投稿タイプごとに用意した専用シート（タロットポスト／情弱ポスト／開運ポスト／
   HSPあるあるポスト／数秘術ポスト）に対し、`GenerationService`の対応する関数を手動実行して
   本文を生成する。生成方法はタイプによって異なる（後述）。生成された行の承認ステータスは
   「未承認」になる。
2. **人による確認・承認**
   各シート上で本文（タロットは画像・カードも）を確認し、承認ステータスを`OK`または`NG`に変更する。
3. **投稿キューへの自動転記**（1時間おき・`transferCycle`）
   各タイプのシートから「承認ステータス=OK かつ 転記ステータス=未転記」の行を、
   1日の内訳（タロット3・情弱4・開運1・HSPあるある1・数秘術1 = 計10件）に従って
   生成日時が古い順に必要数だけ取得し、投稿キューシートへコピーする。コピー元行は
   転記ステータスを「転記済み」に更新する（重複防止）。あるタイプの承認済み行が必要数に
   満たない場合は無理に埋め合わせず、その日はその分だけ投稿本数が減る。詳細は
   [投稿キューへの自動転記について](#投稿キューへの自動転記について)を参照。
4. **投稿巡回**（15分おき・7:00〜24:00・`postingCycle`）
   投稿予定日時を過ぎている行を検出し、① 画像（あれば）＋本文で本体投稿 → ② その投稿に対して
   リプライ本文①②③（あれば）を順番に投稿、の順で実行する。投稿キューシートに来る時点で
   既に承認済みのため、ここでは承認確認を行わない。本体投稿が成功した時点で投稿ステータスを
   「本文投稿済み(リプライ未完了)」にして即座に保存するため、リプライの途中で失敗しても、
   本体の再投稿や投稿済みリプライの重複投稿を起こさず次回サイクルで再開できる。
5. **トークン自動更新**（毎日3:00・`tokenRefreshCheck`）
   Threadsの長期アクセストークン（60日有効）の残り期限が7日以内になったら自動更新する。

## シート構成

### 投稿キューシート（スケジュール管理・投稿実行専用。生成は行わない）

| 列 | 項目 | 内容 |
|---|---|---|
| A | No | 行ID |
| B | 投稿タイプ | タロット／情弱／開運／HSPあるある／数秘術（表示・監査用） |
| C | 投稿予定日時 | 転記時にTransferServiceが自動算出 |
| D〜F | 画像1〜3 | タロットのみ使用（Driveファイル ID）。他タイプは空欄 |
| G | 投稿本文 | 転記時にコピーされる本体投稿文 |
| H〜J | リプライ本文①〜③ | 転記時にコピーされる。空欄の分はリプライ投稿がスキップされる |
| K〜M | リプライ①〜③投稿ID | 各リプライ投稿のThreads投稿ID（再実行時の重複投稿防止・進捗管理に使用） |
| N | 投稿ステータス | 未投稿 / 本文投稿済み(リプライ未完了) / 投稿済み / 投稿エラー |
| O | 実投稿日時 | 本体投稿の実績日時 |
| P | Threads投稿ID | 本体投稿のID |
| Q | エラーメッセージ | 直近のエラー詳細 |
| R | 最終更新日時 | 自動更新 |

### 投稿タイプ別シート（共通列）

5つのシート（タロットポスト／情弱ポスト／開運ポスト／HSPあるあるポスト／数秘術ポスト）は、
以下の列を共通で持つ。

| 項目 | 内容 |
|---|---|
| 投稿本文 | 生成された本体投稿文 |
| リプライ本文①〜③ | 本体投稿へのリプライ本文（タロットは自動生成。他タイプは運営が任意で手動入力してよい） |
| 承認ステータス | 未承認 / OK / NG（NGの行は転記対象から除外される） |
| 転記ステータス | 未転記 / 転記済み（転記時に自動更新） |
| 生成日時 | 生成バッチ実行時に自動記録（転記時の優先順位＝古い順に使う） |

### 投稿タイプ別シート（タイプごとの追加列）

| シート | 追加列 | 内容 |
|---|---|---|
| タロットポスト | 質問、画像1〜3、カード①〜③ | 質問は手動入力。画像・カードは生成時に自動で埋まる |
| 開運ポスト | 日付、開運日 | ともに生成時に自動で埋まる（開運日カレンダーを参照） |
| 数秘術ポスト | テーマ、グループ | ともに手動入力（グループは1〜6 または 7〜9・11・22・33） |
| 情弱ポスト／HSPあるあるポスト | なし | 共通列のみ |

## 生成方法（タイプごとに異なる）

- **タロット**（`generateTarotBatch`）: タロットポストシートの「質問が入っていて投稿本文が空」の
  行を対象に、カード抽選・画像解決・リプライ本文生成・本体投稿文の組み立てをまとめて行う。
  あらかじめ「質問」列に入力しておいた分だけ処理される。
- **数秘術**（`generateNumerologyBatch`）: 数秘術ポストシートの「テーマが入っていて投稿本文が空」の
  行を対象に生成する。**`ClaudeService.generateNumerologyCaption(theme, group)`はプロンプト未提供の
  ため未実装**。実装されるまではこの関数はエラーになる（行ごとにログへ記録されるだけで停止はしない）。
- **情弱／HSPあるある**（`generateJoujakuBatch` / `generateHspAlarmBatch`）: 手動実行1回につき、
  対応するClaude生成関数を10回呼び出し、生成結果をシートに10件追加する。
- **開運**（`generateKaiunBatch(daysAhead)`）: 「開運日カレンダー」シートを参照し、翌日から
  `daysAhead`日分（省略時30日）のうち、開運日がありまだ生成していない日付だけをまとめて生成する。
  GASの実行時間制限（6分）に引っかかる場合は、`generateKaiunBatch(14)`のように日数を減らして
  複数回に分けて手動実行する。

いずれも投稿ステータス列は持たない代わりに投稿本文が空かどうかで生成要否を判定するため
（数秘術・タロットの場合）、生成に失敗した行は投稿本文が空のまま残り、次回同じ関数を実行すれば
自動的に再試行される。生成タイプ別シートにはエラーメッセージ列を設けていないため、失敗の詳細は
実行ログシートおよびApps Scriptの実行トランスクリプトで確認する。

## 投稿キューへの自動転記について

`TransferService.runTransferCycle()`が1時間おきに実行され、「翌日」ぶんについて次の処理を行う。

1. 投稿キューシートに既に存在する「翌日」の行を投稿タイプ別に集計する
2. タイプごとに `不足数 = クォータ(Config.POST_TYPES) - 既存件数` を計算する
3. 不足があるタイプについて、そのタイプのシートから「承認ステータス=OK かつ 転記ステータス=未転記」の
   行を生成日時の古い順に不足数だけ取得し、投稿キューへ追加する（コピー元の転記ステータスは
   「転記済み」に更新）
4. 供給不足のタイプはそのまま件数が減る（無理な埋め合わせをしない）

新しく追加される行の投稿予定日時は、その日に既に確定している件数を起点に、次の空きスロットから
順番に割り当てられる（スロット自体は7:00〜24:00を10等分した既存のスケジュールをそのまま使う）。
何度実行しても安全（冪等）：実行のたびに転記済み件数を数え直すため、同じ行が二重に転記されることはない。

## セットアップ手順

### 1. スプレッドシートとスクリプトの用意

1. 新規Googleスプレッドシートを作成する。
2. 「拡張機能」→「Apps Script」を開き、このスクリプトを紐づける（コンテナバインド型）。
3. `src/` 配下の各ファイルをApps Scriptエディタにコピーする（`.gs`拡張子で保存、`appsscript.json`は「プロジェクトの設定」から表示・編集）。
   `clasp` を使う場合は `clasp push`（`rootDir: src`）でも可。

### 2. スクリプトプロパティの設定

「プロジェクトの設定」→「スクリプト プロパティ」で以下を設定する。

| キー | 内容 |
|---|---|
| `CLAUDE_API_KEY` | Claude APIキー |
| `CLAUDE_MODEL` | （任意）モデルID。未設定時は `claude-sonnet-5` |
| `THREADS_ACCESS_TOKEN` | Threads長期アクセストークン |
| `THREADS_USER_ID` | Threadsのユーザー（アプリ）ID |
| `THREADS_TOKEN_EXPIRES_AT` | トークン取得時の有効期限（ISO8601、例: `2026-09-25T00:00:00Z`） |
| `ALLOWED_DRIVE_FOLDER_ID` | タロットカード画像を置くDriveフォルダID |

### 3. 画像フォルダの共有設定

- `ALLOWED_DRIVE_FOLDER_ID`のフォルダに、カードごとの画像（`カード名_正逆_①②③.png`）を配置し、
  フォルダを「リンクを知っている全員」に共有しておく（Threads側のサーバーが画像を取得できるようにするため）。
- 「カード意味」「開運日カレンダー」シートは、このスプレッドシート内に用意しておく。

### 4. 初期化

Apps Scriptエディタで`initializeSpreadsheet`を一度だけ手動実行する。以下のシートと見出し行が
作成される（「カード意味」シートは既存のデータをそのまま使うため対象外）。

- 投稿キュー／設定／トークン状態／実行ログ／開運日カレンダー
- タロットポスト／情弱ポスト／開運ポスト／HSPあるあるポスト／数秘術ポスト

続けて`installTriggers`を実行し、転記・投稿巡回・トークン更新の3トリガーを作成する。

初回実行時、Drive/スプレッドシート/UrlFetchApp等の権限承認が求められるので許可する。

### 5. 運用

1. 各投稿タイプ別シートに、必要な入力列（タロットは「質問」、数秘術は「テーマ」「グループ」）を
   入力しておく。開運・情弱・HSPあるあるは入力不要（開運日カレンダー参照 or まとめて自動生成）。
2. `GenerationService`の対応する関数（`generateTarotBatch`など）を手動実行して本文を生成する。
3. 各シート上で生成内容を確認し、承認ステータスを`OK`（またはNG）に変更する。
4. 1時間おきの`transferCycle`が、承認済みの行を投稿キューへ自動転記する。
5. 投稿キューに転記された行は、投稿予定日時になると自動投稿される。

## タロットカード抽選について

- カード意味は投稿キューと同じスプレッドシート内の「カード意味」シート
  （列構成: A=カード名, B=向き, C=意味, D=キー(未使用)）で管理する。
- 抽選はカード名でグルーピングしてから重複なく3件選ぶため、同じカードの正逆違いが重複することはない。
- 画像は`ALLOWED_DRIVE_FOLDER_ID`のフォルダから、`カード名_正逆_①②③.png`
  （例: `節制_正_①.png`）というファイル名で検索して取得する。カード名・向きの表記は
  カード意味シートの表記とファイル名が完全一致している必要がある。

## 開運日カレンダーについて

- 投稿キューと同じスプレッドシート内の「開運日カレンダー」シート
  （列構成: A=日付, B=曜日, C=開運日(複数ある場合はカンマ区切り、例: `大安,一粒万倍日`)）を参照する。
- `KaiunService.findLuckyDaysForDate(date)`で指定した日付に該当する開運日名の配列を取得できる
  （該当なしの場合は空配列）。A列は文字列(`yyyy-MM-dd`形式)・Date型のどちらで入力されていても
  正しく比較できるようになっている。
- `GenerationService.generateKaiunBatch`が、開運ポストシートへの一括生成時にこれを使う。

## 情弱ポスト（拡散狙いのフックポスト）について

- `ClaudeService.generateJoujakuCaption()`で本文を1件生成する（引数なし）。画像・リプライは無く、
  本文のみのテキスト投稿（`ThreadsService.publishPost`の画像0枚パス＝TEXTコンテナ）を想定している。
- 元のプロンプトは5パターンを一度に出力する仕様だったが、自動化のため「フックの種類・メッセージの
  方向性をランダムに1組だけ選び、1パターンのみ出力する」よう`buildJoujakuPrompt_`内で調整している
  （フック・方向性の抽選自体はコード側では行わず、プロンプトの指示に従ってClaude側で行わせる）。
- 「有効期間」は実際の日付を渡さず、プロンプトの指示で「〇日〜〇日」「今日中」などのプレースホルダー
  表現のまま出力させる（実日付への書き換えは運営が投稿前チェック時に手動で行う想定）。
- 各パターン末尾に付く「（フック種類×メッセージの方向性）」のようなメモ書きは出力させない指示を
  入れているが、保険として`stripTrailingCombinationMemo_`で応答末尾のその形式のかっこ書きを機械的に除去する。

## HSPあるあるポストについて

- `ClaudeService.generateHspAlarmCaption()`で本文を1件生成する（引数なし）。画像・リプライは無く、
  本文のみのテキスト投稿（`ThreadsService.publishPost`の画像0枚パス＝TEXTコンテナ）を想定している。
- 元のプロンプトは5パターンを一度に出力する仕様だったが、自動化のため「テーマ・構成パターン（A〜E）を
  ランダムに1組だけ選び、1パターンのみ出力する」よう`buildHspAlarmPrompt_`内で調整している
  （テーマ・パターンの抽選自体はコード側では行わず、プロンプトの指示に従ってClaude側で行わせる）。
- 各パターン末尾に付く「（テーマ×構成パターン）」のようなメモ書きは出力させない指示を入れているが、
  保険として情弱ポストと共通の`stripTrailingCombinationMemo_`で応答末尾のその形式のかっこ書きを
  機械的に除去する。

## 開運ポストについて

- `ClaudeService.generateKaiunCaption(date, luckyDays)`で本文を1件生成する。
  `date`は対象日（Dateオブジェクト）、`luckyDays`は`KaiunService.findLuckyDaysForDate(date)`で
  得られる開運日名の配列（例：`['大安', '一粒万倍日']`）。画像・リプライは無く、本文のみの
  テキスト投稿（`ThreadsService.publishPost`の画像0枚パス＝TEXTコンテナ）を想定している。
- 元のプロンプトは「日付範囲を受け取り、ウェブ検索で開運日を調べたうえで複数日分の投稿をまとめて作る」
  仕様だったが、開運日の判定は`KaiunService`側で既に済んでいるため、`buildKaiunPrompt_`内で
  ウェブ検索の指示（STEP1）を削除し、`date`・`luckyDays`を入力データとしてそのまま渡す形に調整した。
  マニアックな開運日（大明日・母倉日・天恩日・神吉日・鬼宿日・天一天上・月徳日・己巳の日）の定義は、
  本文中で意味を一言添える際の参考として引き続きプロンプトに含めている。
- 「対象日の選び方」「出力の順番（前半/後半に分けて確認）」など、複数日をまとめて処理する前提の
  指示は削除し、1回の呼び出しにつき1件の投稿本文のみを出力させる。
- 参考ポストは、本体投稿とリプライへの分割（「↓」区切り）を前提とした⑥⑦⑨を除外し、
  単独の投稿として完結する①②③④⑤⑧のみを使用する（この投稿タイプにはリプライを付けないため）。
- 日付の表示形式（例：「7月6日（日）」）は`Utils.formatJapaneseDate(date)`で組み立てる。

## 画像URLについて（設計上の注意）

当初は「Apps ScriptのWebアプリ(doGet)で許可フォルダのファイルIDのみ受け付ける画像プロキシ」を
実装していましたが、**Google Apps ScriptのWebアプリはTextOutput/HtmlOutputしか返却できず、
画像のようなバイナリを直接配信することができない**ことが実機検証で判明したため（`doGet`から
Blobを直接returnすると「返された値はサポートされている戻り値の型ではありませんでした」という
エラーになる）、この方式は廃止しました。

代わりに、`DriveService.getPublicImageUrl`でDriveファイルIDから
`https://lh3.googleusercontent.com/d/<ファイルID>` 形式の直リンクを組み立てて、
Threads APIの`image_url`にそのまま渡す方式にしています。「許可フォルダ内の画像のみ使う」という
制限は、取得時点でのゲートではなく、**TarotServiceが画像を許可フォルダ内でしか検索しないこと**、
および**PostingServiceが投稿直前に`DriveService.assertImagesAllowed`で再検証すること**
（承認後にシートが編集された場合の保険）の組み合わせで実現しています。

対象ファイルはDrive上で「リンクを知っている人」に共有しておく必要があります。

## 注意事項

- Threads APIのエンドポイント・パラメータ仕様は変更される可能性があるため、実装後に
  実際のレスポンスを確認しながら調整してください（特にリプライ投稿時の`reply_to_id`パラメータ）。
- 数秘術ポストは、`ClaudeService.generateNumerologyCaption(theme, group)`のプロンプトを
  いただき次第、他タイプと同様の形で実装します。
